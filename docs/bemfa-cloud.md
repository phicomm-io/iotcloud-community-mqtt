# 巴法云云端转发

本方案运行于平台后台。设备继续连接原平台 MQTT，不需要增加第二路 MQTT、线程或固件功能；关闭网页后仍可通过小爱同学控制设备。模块直连方案单独保留在 `feat/dual-mqtt-bemfa`，不要同时映射同一设备主题。

## 用户配置

1. 将 TMCP TC1 或 A1 连接到当前平台账号，确认设备在线。Legacy TC1、M1 和仅连接第三方 Broker 的设备暂不支持。
2. 在巴法云控制台创建主题，并取得自己的私钥（API Key）。这里使用私钥认证，不使用巴法云登录密码，也不使用 AppID / SecretKey 认证方式。
3. 在平台“设置 → 巴法云”中填写私钥，添加设备通道与主题的映射，打开转发开关并保存。
4. 按[巴法云小爱同学说明](https://cloud.bemfa.com/docs/src/speaker_mi.html)完成账号绑定和设备同步。

| 设备通道 | 主题后缀 | 支持的控制 |
| --- | --- | --- |
| TC1 插孔 1–6，各自映射 | `001` | 开、关 |
| A1 风扇 | `003` | 开、关、四档风速 |
| A1 灯环 | `002` | 开、关、1–100% 亮度 |

风扇四档对应 20%、50%、75%、100%，关闭对应 0%。设置风速会转入手动模式。灯环控制保留当前颜色、灯效及常亮规则；回传状态反映实际可见状态。未映射的插孔不会被转发控制。

密钥输入框留空保存可保留已存密钥。“启用巴法云转发”关闭后保留配置；“清除配置”停止转发并删除密钥及映射。密钥不会通过读取接口返回，也不会存入浏览器持久存储。

同一私钥只能在一个平台节点启用：巴法云私钥认证使用私钥作为 MQTT 客户端 ID，其他使用相同 ID 的连接会互相挤掉。切换平台节点不会自动迁移配置；先在原节点关闭转发。

## 转发行为

- 仅接收映射原主题上的新指令；忽略 retained 控制消息和重复投递标记。
- 检查账号、设备归属和配置版本，按设备实际 MQTT principal 路由，不按 MAC 单独猜测归属。
- 设备离线、配置失效、队列满或同设备仍有未完成指令时丢弃新控制；恢复连接后不会补发。每设备最多一条未完成控制，最多等待 10 秒。
- 控制使用独立 `request_id`，QoS0、非 retained；不自动重试执行。网络丢包可能导致一次操作未执行，应查看实际状态后重新操作。
- 状态更新到 `<主题>/up`，使用设备实际状态而不是请求值。设备首次上线会读取一次状态，控制回执后再确认状态；空闲时不轮询设备。
- 断线会清空在线及状态缓存，重新连接后确认状态再接受操作。

[巴法云 MQTT 官方文档](https://cloud.bemfa.com/docs/src/mqtt.html)说明私钥认证、TLS 9503 和 `/up` 状态更新。本服务只使用该固定 TLS 地址并验证服务器证书。

## 运维与备份

后台启动会迁移 SQLite，增加 `bemfa_integrations` 表。凭据及映射使用 AES-256-GCM 加密，密钥文件为 `<db_path>.bemfa.key`，默认 `/data/app.db.bemfa.key`，首次启动生成且权限为 0600。标准 Compose 的 `/data` 持久卷会保存它。

**数据库和密钥文件必须一起备份、一起恢复。** 丢失密钥无法解密已有配置；不要把其他安装的密钥覆盖到现有节点。若文件丢失，原配置无法恢复，可在用户设置中清除后重新填写。新增存储仅在首次启动和保存配置时写入，账号密码修改不会改变加密密钥。

运行后台的服务器需能向 `bemfa.com:9503` 发起出站 TLS 连接。不需要新增入站端口。后台会更新 manager 角色，增加 TMCP `state`、`availability`、`result` 接收及 `command` 发送权限，普通账号权限保持原来的账号隔离。

API 位于 `/api/integrations/bemfa`，沿用平台会话与来源检查：GET 读取无密钥配置及状态；PUT 完整替换开关与映射、私钥留空保留；DELETE 清除。每账号最多 64 个映射，主题和设备通道不能重复，主题为字母、数字或下划线、最长 64 字符且符合通道后缀。

## 本地验证

```sh
cd backend
go test -race ./...
cd ..
scripts/test-integration.sh
```

前者包含两个本地 MQTT wire fixture 的双向转发、权限撤销和不补发测试，不连接外网。后者仅启动临时本地 Mosquitto，检查真实动态权限、迁移和持久化。它们不控制实机、不使用真实巴法云账号。

平台页面测试位于配套前端仓库 `frontend/tests/bemfa-cloud.mjs`。按前端锁定产物发布流程部署前后端后，用户再自行填写 API Key；本分支不预置账号或密钥。

## 未发布分支的离线预览

本分支锁定同分支前端提交的 SHA 和压缩包哈希。正式发布时需先将该提交对应的前端产物发布到锁文件指定的 GitHub Release，再构建常规 web 镜像。当前工作区已生成本地产物，尚未创建远端 Release。

在前端仓库提交源码后执行 `python3 tools/build_release.py`（先安装 `requirements-build.txt`），取得 `build/frontend.tar.gz`。在后台仓库运行：

```sh
FRONTEND_ARCHIVE=/absolute/path/to/iotcloud-community-frontend/build/frontend.tar.gz scripts/test-browser-compose.sh
```

脚本先核对本仓库 `frontend.lock.json` 的提交与 SHA-256，再用 `web/Dockerfile.offline` 构建预览镜像，启动随机端口和临时数据的 Compose 环境，完成测试后清理。无需发布前端产物，也不会替换生产容器。
