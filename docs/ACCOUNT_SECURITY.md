# 统一账号与管理鉴权

网站、管理员控制台、MQTT 使用同一套账号，网站与 MQTT 密码可独立修改。管理员只是用户的管理角色，并不是第二套登录身份。

## 用户名与登录别名

新平台用户名和 MQTT 别名均为 3–32 个 ASCII 字符，只允许字母、数字、下划线、点和连字符，保留大小写。`__` 前缀、Broker 管理名和配置的初始化管理员名不能用于普通注册或 MQTT 别名。首次初始化管理员同样限制为 3–32 个字符。

公开注册、管理员创建、GitHub 新用户注册和 MQTT 别名 API 使用相同的服务端校验；无效用户名返回 HTTP 400，`code` / `message_key` 为 `e.1ef6a7c0d805`，在写入账户、OAuth 流程或 Broker 前拒绝。用户名长度限制用于控制十六进制账号 scope 和设备主题的大小。

验证邮箱是独立的登录别名，最长 254 字节，可包含邮箱格式所需的 `@` 和 `+`；邮箱不会作为新 MQTT 身份。已存在的长用户名或邮箱形式的主账号不截断、不改名，密码和已绑定 GitHub 登录继续可用。需要较短 MQTT 身份时，登录后调用 `PUT /api/auth/alias`，提交 `{"alias":"short_name","password":"当前MQTT密码"}`。每个账号支持一个 MQTT 别名，别名使用独立 scope、共享设备归属和权限；登录响应中的 `mqtt_username` 指向有效的短别名。

## 登录与权限

- 从 `/login` 调用 `POST /api/auth/login`；登录与 `GET /api/auth/me` 返回 `username`、`is_admin`。
- 网站使用随机、不透明的 `phicomm_session` Cookie：HttpOnly、SameSite=Lax、30 天有效；SQLite 只保存会话 token 的 SHA-256 摘要。HTTPS 部署配置 `cookie_secure: true`。
- 密码登录使用独立的网站密码哈希；旧账号首次成功登录时验证 Broker 凭据并建立网站密码哈希。应用数据库不保存用户明文密码。管理员 MQTT 账号仍只授权其自己的设备主题，不能读写 Broker 管理主题或其他用户的设备。
- 可选 [GitHub 登录](GITHUB_LOGIN.md) 使用 GitHub 数字 ID 绑定统一账号，保留数据库中的原有角色和设备权限；新用户不会获得管理员角色。已有账号须先登录后绑定，不按邮箱或用户名自动合并。解绑需要网站密码，撤销该账号全部网站会话。
- 可信跨域前端通过 `X-IotCloud-Session` 获取同一网站会话并以 Bearer 传递；按后端来源隔离保存，不依赖第三方 Cookie。来源需精确配置到 `allowed_origins`。
- 前端只给管理员显示管理入口，路由也检查管理权限；前端限制不能替代服务端鉴权。
- 所有 `/api/admin/*` 管理请求都检查有效网站会话、账号 active 状态和数据库中的当前管理员角色。匿名请求返回 401，普通用户返回 403。角色撤销后，下一个管理请求立即被拒绝。
- 所有会话写请求执行 Origin 同源校验，角色管理也不例外。旧 `/api/admin/login` 和独立 Bearer token 认证已移除。
- 退出登录撤销对应会话；修改/重置密码、删除用户撤销该用户的网站会话。前端定期刷新管理角色，角色撤销时隐藏入口或离开管理页。

## 管理角色

`GET /api/admin/users` 返回每个用户的 `role`（`user` 或 `admin`）。

管理员通过 `PUT /api/admin/user/<URL编码用户名>/role` 提交：

```json
{"role":"admin"}
```

提交 `{"role":"user"}` 撤销管理权限。用户必须处于 active 状态。公开注册和普通用户接口不能设置角色。系统拒绝删除或降级最后一个有效管理员，返回 409。

## 初始化与旧版升级

首次启动以配置的 `admin_username` 和 `admin_password_file` 初始化统一管理员，创建其 Broker 普通设备账号与数据库管理角色。初始化完成标记持久保存；后续启动不重新授予已撤销的角色、不恢复删除的账号，也不使用密码文件覆盖修改后的密码。

若配置的管理员名称已经属于现有普通用户或 Broker 客户端，则拒绝自动采用该身份、拒绝自动提权。升级过程中创建的账号使用单独的 bootstrap 状态，初始化全部完成前不能网页登录。

管理角色存储于 `user_roles`，通过外键随用户删除。管理操作使用结构化 API，不支持编辑原始 ACL；服务不挂载 Docker socket，Broker 权限变更走经过验证的 TLS 管理连接。
